Solving Problems by Searching
▶Consider an agent with a goal and a set of actions it can
perform to reach the goal (a goal-based agent).▶The goal is the state of affairs the agent wants to bring about.
▶The difficulty is deciding the order in which the actions are
carried out.
▶The agent thus wants to compute a sequence of actions
leading to the goal, and possibly satisfying an optimality
condition (e.g. being as cheap as possible).
▶Describing the goal, the relevant states, the possible actions
and the optimality criterion is called problem formulation.
▶Looking for a sequence of actions that leads to a goal state
(and is optimal) is called search.

Search is Everywhere
The algorithms in this lecture are 60 years old and still run, every
day, inside:
▶Route planning: Google Maps / satnav (search over a road
graph);▶Robotics and warehouses: an Amazon or Ocado robot
planning a collision-free path;
▶Game AI: from Deep Blue’s chess search to AlphaGo’s
Monte-Carlo treesearch;
▶LLM agents (2023–): a model that plans, calls a tool,
observes and backtracks is exploring a tree of possible action
sequences.
The vocabulary we now define — state, action, frontier, branching
factor — is the vocabulary used in all of these.

Problem Formulation: the Search Graph
▶First determine the set Sof possible states of the problem.▶The search graph for the problem is then given by:
▶the set Sof states;
▶a start state sstartfrom S;
▶a set Sgoal⊆Sof goal states;
▶a set Aof actions taking the agent from one state in Sto
another; we often do not name the actions but simply say
which states are reachable from a state by a single action;
▶a cost function stating how expensive an action is. If all actions
are equally expensive we set cost( a) = 1 for every action a.
▶A solution is a sequence of actions which, performed in sstart,
takes the agent to a state in Sgoal. A solution is optimal if
there is no cheaper solution.
We now determine the search graph for each of the four problems.

and simply draw an arrow from a state sto each state
reachable from sby one action. These are the successor
states of s. Conversely, s′is a predecessor of sifsis a

6: select and remove from frontier a path s0. . .sk

11:end while

Generic Algorithm for Search: comments
▶The input is a start state s0, a way of producing the successors
of a state, and a way of testing whether a state is a goal state.▶The algorithm maintains a set frontier of paths, initially just
the path s0.
▶While frontier is non-empty, it selects and removes a path
from it (we say the path is expanded).
▶If the last state of that path is a goal state, it terminates and
returns the path.
▶Otherwise it adds to frontier every path obtained by
appending one successor.
▶Then it repeats, selecting from the updated frontier.
▶Note: the frontier stores paths, not states — we must return
the route, not just the news that a goal exists.

What the Generic Algorithm Leaves Open
▶Which path s0. . .skdo we select and remove from the
frontier?Equivalently: which path do we expand? (Or
loosely: which state skdo we expand?)
▶In which order do we add the new paths s0. . .sksto the
frontier?
The second question we ignore (don’t-care non-determinism). The
first question is the algorithm:
▶Breadth-first search (BFS): always select the path first added
to the frontier (frontier as a queue, FIFO);
▶Depth-first search (DFS): always select the path last added to
the frontier (frontier as a stack, LIFO).
One line of difference. Completely different behaviour.

2;
▶Then expand all paths produced in that step — depth 3;
▶and so on.
In general: expand all paths of length nbefore any path of length n+ 1.
Implementation: the frontier is a FIFO queue — new paths go to
the back.

Depth-First Search (DFS)
▶Start by expanding the start state;
▶Select one of the resulting paths and expand it;
▶Select one of those paths and expand it; and so on.▶Always select the longest (deepest) path: follow one branch of
the tree to the end, then backtrack.
Implementation: the frontier is a LIFO stack — new paths go to
the front.

Properties of Search Strategies
▶Completeness: does the algorithm always find a solution if one
exists?YES for BFS, NO for DFS (consider cycles in the search
graph).
▶Optimality: does the algorithm always find a shortest path (a
path of lowest cost)?
YES for BFS, NO for DFS.
▶Time complexity: how many paths are generated?
▶Space complexity: how many paths are held in memory (in
the frontier) at once?
For the last two we first need a way of measuring the size of the
problem.

Measuring the Problem: b,d,m
Time and space complexity are measured in terms of:
▶b— the maximum branching factor of the search tree: the
largest number of successors any state has;▶d— the depth of the optimal solution: the length of the
shortest path from sstartto a goal state;
▶m— the maximum depth of the state space: the length of
the longest path in the search tree (may be ∞).
Note m=∞whenever the search graph contains a cycle: our
search tree simply grows paths, and nothing stops it from going
round the cycle forever.

Properties of Breadth-First Search
Fact. In a search tree with maximum branching factor bthere are
at most bdpaths of length d, and at most 1 + b+b2+···+bd
paths of length at most d.▶Time: if the shortest path to a goal has length d, in the worst
case BFS generates
1 +b+b2+···+bd
paths before reaching a goal (exponential).
▶Space: in the worst case the frontier holds bdpaths
(exponential).
▶Complete: guaranteed to find a solution if one exists.
▶Optimal: always finds a shortest solution (when all actions
cost the same).
Space, not time, is what usually kills BFS in practice.

Properties of Depth-First Search
▶Not complete: DFS may follow an infinite branch and never
find an existing solution.▶Not optimal: the solution found need not be the shortest one
(we saw SAEG vsSBG ).
▶Time: if the longest path from the start state has length m, in
the worst case DFS generates
1 +b+b2+···+bm
paths (exponential). If m=∞, DFS may not terminate at all.
▶Space: the frontier holds at most
b×m
paths. If DFS does find a solution, its memory requirement is
far smaller than that of BFS — linear rather than exponential
in the depth.

Note: Big O-Notation
A function g is in O(f) if there exist a positive constant c and a
threshold n0such that
|g(n)| ≤c×f(n)
for all n≥n0. In computer science, O-notation lets us describe
how an algorithm’s running time or memory grows with the input
size while ignoring hardware speed and implementation details.
This matters most for scalability: two methods that look similar on
small inputs can diverge enormously as the problem grows, which
is exactly the combinatorial explosion.
