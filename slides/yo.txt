Recap
Basic uninformed tree search algorithms:
▶Breadth-first search (BFS): expand the oldest path in the
frontier (FIFO queue). Complete and optimal, but memory
hungry.▶Depth-first search (DFS): expand the newest path in the
frontier (LIFO stack). Very modest memory use, but
incomplete (it can get lost down an infinite branch) and not
optimal.

Terminology and notation (used from now on)
▶b= branching factor: maximum number of successors of a
state.
▶d= depth of the shallowest goal: length of a shortest path
from the start state to a goal state.
▶m= maximum depth of the search tree ( m=∞if paths can
be arbitrarily long).
▶ℓ= depth limit that weimpose (introduced below).▶A path is generated when it is put on the frontier; it is
expanded when it is taken off the frontier and its successors
are generated.
▶Complete: if a solution exists, the algorithm finds one.
▶Optimal: the solution returned is a shortest path.
▶Time complexity: number of paths generated. Space
complexity: maximum size of the frontier.

Recap: BFS and DFS side by side
Complete? Optimal? Time Space
BFS yes yes O(bd)O(bd)
DFS no no O(bm)O(b m)
The whole of this section is about the gap in this table: BFS has
the good guarantees, DFS has the good memory behaviour. Can
we have both?

Depth Limited Search (DLS)
▶Depth-first search has one very desirable property: space
complexity.▶But if a wrong path is expanded (with no solution on it), then
the search may take a very long time, or may not terminate at
all.
▶Idea: fix a depth limit ℓand never expand a path of length ℓ.
▶So DLS = DFS + “stop going deeper at level ℓ”.
▶Useful if you know (or can bound) the length of a shortest
solution.

Example: a safe depth limit for Rubik’s Cube
Recall from Section 2: the cube has 43 ,252,003,274,489,856,000
states. So how deep could a solution possibly be?▶In 2010 it was proved (by exhaustive computer search) that
every configuration can be solved in at most 20 moves. (This
number is sometimes called God’s number.)
▶Hence ℓ= 20 is a provably safe depth limit — and DLS with
ℓ= 20 is complete for the cube, even though plain DFS could
wander forever.
▶The state space is enormous, but it is shallow: b≈18,
d≤20. This is exactly the regime in which depth-limited and
iterative-deepening methods are good options.
Moral: knowing a bound on dcan be worth more than knowing
anything about the size of the state space.

Properties of Depth Limited Search (DLS)
▶Not complete: if d> ℓthen DLS returns failure although a
solution exists. If d≤ℓ, DLS does find a solution.▶Not optimal: it returns the first solution it stumbles on, which
need not be a shortest one.
▶Time: in the worst case DLS generates
1 +b+b2+···+bℓ=O(bℓ)
paths.
▶Space: the frontier holds at most bsiblings for each of the ℓ
levels of the current branch, so at most b·ℓpaths, i.e. O(bℓ).

Quiz (2 minutes, talk to your neighbour)
A state space has b= 4 and a shortest solution at depth d= 6.
You run DLS with limit ℓ= 4.
1. What does the algorithm return?
2. Does it terminate?
3. You now rerun it with ℓ= 8. Is the returned solution of length
6?Answers: (1) failure — no solution has length ≤4; (2) yes, always:
the tree below depth ℓis finite; (3) not necessarily — DLS is not
optimal, it may return a solution of length 7 or 8.

Iterative Deepening Search (IDS)
▶Problem: if we guess a depth limit that is too small, DLS is
incomplete. If we guess one that is too large, we lose the
benefit.▶Idea: don’t guess. Try every limit in turn.
▶run DLS with limit 0; if a solution is found, return it;
▶otherwise run DLS with limit 1; then 2; then 3; . . .
▶The first solution found is at depth d, so it is a shortest
solution.
▶Useful when the search space is large and the depth of the
solution is unknown — which is the normal situation.

General Algorithm for Iterative Deepening (IDS)
Call DLS as a subroutine:
1:Input: a start state s0
2: for each state sthe successors of s
3: a test goal( s) checking whether sis a goal state
4:
5:Set DepthLimit := 0
6:repeat
7: Result := depth limited search(DepthLimit)
8: ifResult is a path s0...skthen
9: return s0...sk(and terminate)
10: else DepthLimit := DepthLimit + 1
11: end if
12:until FalseEvery iteration starts from scratch: the tree above the new limit is
regenerated. This looks wasteful. The next slides show why it is
not.

Properties of Iterative Deepening (IDS)
▶Complete: if a solution exists (and bis finite) IDS finds one,
because the limit eventually reaches d.▶Optimal: the solution returned is a shortest path — no
solution of length <dwas missed, since all smaller limits
failed.
▶Time: let dbe the length of the shortest path to a goal state.
Then in the worst case IDS will look at
1 + (1 + b) + (1 + b+b2) +···+ (1 + b+b2+···+bd)
paths before reaching a goal state.
▶Space: O(b d) — the same as DFS, since each iteration is
just a DLS.
So IDS has the guarantees of BFS at the memory cost of DFS.

IDS versus BFS: is the regeneration expensive?
Example: b= 10, d= 5.
▶BFS generates 1 + b+···+b5= 111 ,111 paths and must
store up to b5= 100 ,000.
▶IDS generates 1 + (1 + b) +···+ (1 + ···+b5) = 123 ,456
paths and stores only about b·d= 50.
▶Cost: 11% more work. Benefit: 2000 ×less memory.Why so cheap? Because the last level dominates: it contains more
nodes than all the levels above it put together. Redoing everything
above it is almost free.

Avoiding Repeated States
Three options, in order of increasing effectiveness andincreasing
overhead:
1. Do not return to the state you have just come from.2. Do not create paths with a cycle in them (no state occurs
twice on the same path).
3. Do not create paths containing any state that occurred in a
path created earlier — set of reached states.
This turns tree search into graph search.
The trade-off is real: option 3 makes BFS on the grid above
polynomial instead of exponential, but it also destroys the memory
advantage of DFS and IDS, which is a main reason we were using
them. So: BFS is usually run as graph search (option 3); DFS and
IDS usually use option 2.

twice on the same path).
3. Do not create paths containing any state that occurred in a
path created earlier — set of reached states.
This turns tree search into graph search.
The trade-off is real: option 3 makes BFS on the grid above
polynomial instead of exponential, but it also destroys the memory
advantage of DFS and IDS, which is a main reason we were using
them. So: BFS is usually run as graph search (option 3); DFS and
IDS usually use option 2.

Bi-directional Search: good properties
▶Often much more efficient: instead of one search to depth d,
we do two searches to depth d/2.
▶2bd/2is dramatically smaller than bd.▶Example: b= 10, d= 6.
▶BFS examines 1 + b+···+b6= 1,111,111 paths.
▶Bi-directional BFS examines 2 ×(1 + b+b2+b3) = 2,222
paths.
▶The memory requirement drops in the same way: bd/2per
direction rather than bd.
▶Different strategies can be used in the two directions.

Bi-directional Search: problematic properties
▶We must be able to generate predecessors of a state. Easy on
a map (roads run both ways); hard when actions destroy
information (e.g. “delete the file”).▶We need an explicit goal state. If the goal is described by a
property (“a checkmate position”), there may be billions of
goal states to search back from.
▶We need an efficient test of whether a newly generated state
appears in the other frontier — in practice a hash table.
▶Optimality needs care: the firstmeeting point of the two
frontiers is not always on a shortest path. A correct
implementation must finish the current level and compare all
meeting points.
▶Memory is still O(bd/2) per direction: better, but still
exponential. For large dthis remains impractical.

Everything at a glance
Complete? Optimal? Time Space
Breadth-first (BFS) yes yes O(bd) O(bd)
Depth-first (DFS) no no O(bm) O(b m)
Depth-limited (DLS) if d≤ℓ no O(bℓ) O(bℓ)
Iterative deepening (IDS) yes yes O(bd) O(b d)
Bi-directional (BFS both) yes yes O(bd/2)O(bd/2)
Read the table by column: IDS is the sweet spot for uninformed
search — BFS’s guarantees, DFS’s memory. Bi-directional search
beats it on time and space, but only when you can run the state
space backwards from an explicit goal.

Summary
▶More advanced uninformed search techniques:
▶depth limited search — DFS made to terminate;
▶iterative deepening — DFS made complete and optimal;
▶avoiding repeated states — three levels, three different
memory bills;
▶bi-directional search — bdbecomes 2 bd/2, if you can search
backwards.▶These improve substantially on plain BFS and DFS.
▶But they are all still uninformed: they know nothing about
which direction the goal lies in, and remain exponential in d.
Realistic problems need heuristics — the topic of the next
section.
